## Core Notes

### Openings & the roadmap

A good talk opens with a **map**: what it covers and how many parts. Catch the opening and you have a plan for the whole talk.

- Topic: *Today I'm going to talk about…*
- Structure: *I'll divide this into three parts. First… then… finally…*

Count the points — hear *three reasons* and leave three slots in your notes.

### Listing & contrast signposts

Signposts carry no new facts; they tell you the **relationship** between ideas and **where the key point is**.

| Function | Signals |
|---|---|
| Listing | first, then, next, finally |
| Adding | also, moreover, in addition |
| Contrast | however, but, on the other hand, whereas |
| Example | for example, for instance, such as |
| Cause | so, therefore, as a result |
| Key point | the key point is, importantly, note that |
| Summary | in short, to sum up, overall |

Hear *for example* → support is coming (relax a little). Hear *the key point is* → core idea, note it now.

### Point vs. example

The **point** is a general claim; the **example** illustrates it. In notes, write the point at the margin and indent examples under it — don't transcribe every example.

### TED-style talks

One big idea, story arc: hook → problem → idea → evidence → call to action. More scripted and clear than a live lecture, but fast and idiomatic, with image-only slides. **Use redundancy:** speakers repeat and rephrase (*in other words…*) — miss it once, catch it the second time.

### Predict before listening

Read the title, abstract, and slide titles; predict content and vocabulary. Listening then **confirms** predictions instead of decoding from zero.

### Self-check after

How many points? State each in a sentence. Which was claim, which example? What was the speaker's stance? Re-listen to any gap.

### Summary

Openings give the roadmap. Signposts flag logic and the key point. Predict before, retell after.

## Worked Examples

**Example 1.** "Let me turn to my second point." → **sequencing signal**; new point, start a new note slot.

**Example 2.** "Exercise boosts mood. *For instance*, a short walk lifts energy." → *for instance* introduces **support**, not a new point.

**Example 3.** "There are ___ main causes." (roadmap number) → note the number, leave that many slots.

**Example 4.** "It looked cheap. *However*, costs were huge." → *however* flags a **contrast/reversal** — the key part.

**Example 5.** Roadmap note template: topic / number of points / points 1–3 keywords / stance.

## Exercises

1. What does a talk's opening give you, and why listen for it?
2. Classify: however / for instance / to sum up / moreover.
3. How should attention shift at *for example* vs *the key point is*?
4. How do you separate point from example in notes?
5. What does "use redundancy" mean for listening?
6. List three post-listening self-check questions.

**Answer key.**

1) The roadmap (topic plus structure plus number of points); it predicts the whole talk. 2) Contrast: however; example: for instance; summary: to sum up; adding: moreover. 3) for example → detail, relax; the key point is → core, note now. 4) Point at the margin, examples indented under it. 5) Speakers repeat and rephrase; a missed point often returns. 6) How many points / which is claim vs example / the speaker's stance.
